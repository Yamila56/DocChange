## 基线版项目描述存档（最新简历见 RESUME-DOCCHANGE.md）

**DocChange｜基于自研 Agent Harness 的版本化文档变更工作台**

独立开发项目｜2026.10 – 至今

Python、FastAPI、Pydantic、SQLAlchemy、MySQL / SQLite、Redis Streams、BM25、React、Git

- **业务闭环与版本管理：** 面向接口、配置及示例更新中的跨文档维护任务，设计“依据定位—修改提案—差异审核—版本发布”流程；以不可变 Revision 保存正文与检索索引，通过 ChangeSet、hash 绑定审批及版本冲突检查，约束未经审核的修改与过期提案覆盖。
- **Agent Harness 与受控工具：** 实现结构化工具调用、按需检索、批量读取、精确修改和补问循环，结合 Schema 校验、模型预算、超时与持久 Checkpoint 恢复执行；Git 仓库适配器通过只读实现参考、读取证据绑定和临时 Git Index 导出候选补丁，保留原工作树。
- **异步任务与可靠执行：** 基于 FastAPI + SQL Outbox + Redis Streams 解耦任务提交与模型执行，提交返回 HTTP 202；以 Worker Lease/Fencing、独立异步心跳、幂等回执及通知回收处理重复投递和中断恢复。检索计算与仓库文件操作移出事件循环，避免阻塞模型 I/O 和心跳。
- **检索策略与公开量化：** 结合 BM25 依据定位与精确扫描覆盖跨文件标识符；在完整 BEIR SciFact test **300** 查询上测得 Recall@5 **72.68%**、Recall@10 **77.57%**、nDCG@10 **65.23%**，本机 CPU 检索 P95 **19.42 ms**。另保留 SCIDOCS **1,000** 查询的完整结果，用于分析词法检索的适用边界。
- **公开任务与失败分析：** 完成 DoGBench 公开 dev **175** 项任务的 API 工具适配评测，保留逐题轨迹、官方准则评分与 **73** 份候选补丁；全部补丁通过 `git apply --check`。依据预算空占、重复探索和维护面遗漏等失败，补充调用前预算预检、定位式读取、阅读清单与草稿复核。

## 面试中需要讲清的边界

这是个人开发、公开任务验证的原型，未接真实企业用户或业务流量。业务需求来自实现变更后的技术文档维护；已有真实开源仓库任务可以验证任务类型，但不等于证明产品付费需求。

公开评测的[完整报告](evaluation/docchange-public-2026-11-02.md)包含低分与失败。DoGBench 基线综合 **25.61/100**，73 个补丁可应用不代表73个正确；123个需改任务中63个有补丁，15个未命中阻断 P0。SciFact/SCIDOCS 测检索组件，不测修改语义，不能拿来替代 Agent 成功率。

小型工作台支持网页审批并发布 Revision；大仓库适配器目前导出 patch，尚未接成网页审批后的 Git 提交/推送。当前为单 Agent、自研 Harness；文档域已新增可选Dense/RRF/Rerank，默认保留BM25。无多Agent、长期记忆或异步索引服务。Docker 固定检查接口存在，本轮真实文档容器验收未完成，简历技术栈不将其列为本轮已验证能力。

异步不等于并行：API、模型、SQL、Redis 为异步 I/O，检索/文件操作通过线程卸载；单任务中依赖前一步证据的工具顺序执行。一个 Worker 进程逐项处理，可通过多个进程消费。尚未完成文档域吞吐压测，因此不写 QPS、并发提升比例或生产容量。

异步修改后定向工程回归 **35 passed / 2 skipped**；语义检索扩展后文档相关回归 **17 passed**，另有真实ONNX CPU检索的HTTP/后台任务功能冒烟。工程回归与公开检索评测分别记录，不宣称它们证明Agent补丁质量提升。

## 最有说服力的演示顺序

导入技术文档和只读变更依据 → 提交跨文档更新任务并取得 run_id → 查看检索/工具时间线和 ChangeSet 影响清单 → 审核差异及引用 → 批准发布 R2 → 回看 R1 → 演示旧提案因基准版本过期被拒绝。

展示公开检索结果及一份确有增补内容但仍有遗漏的候选补丁，说明“可应用、部分正确、可直接发布”之间的区别。避免用纯拼写更正的高分个例代替复杂任务效果。
