# ADR 0001 — 先建立确定性的模拟业务内核

状态：采用。日期：2026-10-27。

模型不应成为订单、金额或授权的最终裁决者。先实现独立于模型的事务服务，允许无密钥验证其约束；后续 Agent 只通过受控工具调用。

M1 内部 execute 按 proposal → order → policy/item 的固定顺序锁定资源。进入 M3 后必须在其之前锁 run 并检查 fencing；尚未接入时不开放 HTTP execute，也不声称已具备 Worker 崩溃恢复。

本地操作与账本使用同一事务，操作回执有唯一 ID。HTTP Idempotency-Key 只处理相同请求重放；业务层重新校验订单状态和可退数量，不依赖永久的 order+action 唯一键，以允许多次合法的部分退货。

测试的 SQLite 后端只证明功能分支；MySQL 并发测试单独运行并显式区分。合成数据使退款和竞态可安全重复测试，不代表有真实用户或生产业务。

真实 MySQL 测试首次发现：两份提案在锁订单前对不存在的 operation 做 FOR UPDATE，可能产生间隙锁交互并死锁。修正为先锁具体订单行，再查询操作回执；同一订单的操作先串行化。对 1205/1213 增加最多三次、带抖动的本地事务重试；每次完全退出事务后再重试，保留原请求/operation 关联。不对连接断开或提交结果未知自动使用这个重试器。
