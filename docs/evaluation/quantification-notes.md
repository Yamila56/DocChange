# 量化结果的使用边界

日期：2026-10-27。以下来自实际本地运行，不是目标值。

## 检索消融

数据：25 篇短合成政策文档，含过期版本及私有文档；8 条 dev、16 条冻结测试。标签由编码助手构造，尚未独立人工审核。具体数据、模型文件 SHA-256、所有逐题输出和配置见 retrieval-v1-results.json。

- BM25 Recall@1=68.75%，Recall@3=93.75%。
- 纯向量 Recall@1=56.25%，Recall@3=81.25%，没有超过 BM25。
- RRF 混合 Recall@1=62.50%，Recall@3=93.75%。
- 混合+BGE 量化重排 Recall@1=75.00%，Recall@3=100%。
- 相比 BM25，Recall@1 与 Recall@3 均增加 6.25 个百分点，在这个小集上都只多命中一条，不能解读成普遍提升。
- 代价：混合重排 CPU P50≈1343ms、P95≈1468ms；BM25 P50≈0.4ms。默认先保持 BM25，是否启用重排按业务质量/延迟预算选择。

16/16 命中并不证明真实命中率为 100%。全成功情况下普通 bootstrap 会退化到 [1,1]；按二项命中计算的 Wilson 95% 区间约为 80.6%–100%。报告中的 bootstrap 区间不能被当作普遍零不确定性。

## 工程测试

真实 MySQL 子进程测试已经覆盖事务提交前和提交后两个硬退出点，恢复后均仅一笔模拟退款。测试数量为 2，不是覆盖所有可能故障的“100% 恢复保证”。MySQL 并发、Redis 消息丢失、检查点和 SSE cursor 另有专项测试；最终覆盖以最新测试报告为准。

workflow-regression-v1 是无密钥 deterministic demo 控制器的业务状态回归测试。其通过率只能表述为这个回归集上的工程闭环通过率，不能叫大模型准确率、客服解决率或商业上线效果。

## 简历表述原则

可用经核实的范围化表述，例如“实现 BM25/中文 BGE 双路检索及量化重排，在 16 条合成政策测试上 Recall@3 从 93.75% 到 100%，同时分析 CPU 延迟代价”；更推荐完成更大且独立审核的集后替换这些初步数字。

不能写“真实用户满意度提升”“线上退款零重复”“生产级故障恢复率 100%”“官方 τ-bench 成绩”，因为目前没有对应证据。真实模型端到端成功率、成本、重复运行可靠性需配置服务后单独评测。
