# 第一轮真实模型联调准入（不是生产发布验收）

日期：2026-10-27。状态：工程准入门槛已通过，可在用户配置密钥并确认预算后开始。
本轮目的：先验证官方 DeepSeek 能否驱动 ShopResolve 自有协议与业务循环，
并记录协议错误、工具选择错误、任务结果及实际用量。不是刷最终成功率，也不是公开基准成绩。

## 本轮已落实的业务约束

- **能力清单**：ContextBuilder 提供与 Runtime 共用的 capabilities；未实现的换货、商品比较、
  人工工单明确记为 UNSUPPORTED_CAPABILITY，不伪称已办理或已创建工单。混合任务按目标分别收束。
- **授权实体解析**：resolve_order 仅查询当前 owner 的订单，按明确商品词/状态保守筛选。
  多候选、空候选、截断搜索均补问；返回候选持久保存，用户可以明确选择第几个。
  “好的”“退两个”“不要选某单”不是选单授权。模型不能越过解析结果直接读任意候选ID。
  这是受限词法消歧，不声称通用语义理解；负向/排除表达保守补问。
- **资格咨询**：calculate_eligibility 使用确定性业务规则，只读返回订单/政策版本及资格原因，
  不建提案、不批准、不产生退款。探测退货以单件为基准，不是用户已选择数量或最终金额。
  具体订单的“能否退/取消”不能只凭通用政策文本收束。
- **政策证据**：按目标保存检索观察和引用，检查文本哈希和已登记条款覆盖；
  每目标一次初检加最多两次补检索，预留先持久化，重放不会重新领取预算。
  不相关引用不能完成目标，其他目标的引用不能借用。运费、保修、到账时间等未覆盖事项不编答案。
  此检查是有限领域的确定性 scope/coverage，不是通用语义蕴含模型；正式评测仍需人审支持关系。
- **动作前政策核验**：先查授权订单和适用政策，再生成提案；准备事务核对检索版本是否仍活跃。
  政策变更时停止，不把旧解释配给新规则。审批与执行前的订单/政策校验仍保留。
- **执行中断**：已提交 operation 是最终依据。取消、过期、失败收尾会回查回执，补齐尚未保存到
  loop checkpoint 的业务结果；已提交操作不因取消任务消失。真实进程退出和 MySQL 竞争测试单列。
- **Memory**：extractive 摘要带来源消息、来源哈希、文本哈希和版本，随检查点保存。
  结构化金额、目标、proposal/operation 引用不被摘要覆盖。不做跨会话长期画像或完整 TTL 清理。
- **确定性收尾**：已核验的目标全部有处置后，可直接经 CompletionGuard 模板返回，不要求供应商再
  花钱生成“成功总结”。因此业务完成后模型故障不会遮蔽已核实结果。

## 第一次评测的明确范围

数据：evals/data/deepseek-pilot-v1.json，三个合成场景：

1. 查询 order-pending：核实订单，无业务副作用。
2. 取消政策咨询：读取适用证据，无提案、无退款。
3. 明确请求取消并由脚本用户批准：正确订单取消，模拟退款19900分，唯一回执，其他用户订单不变。

模型只接收用户消息和授权工具观察，不接收预期答案。各场景独立临时 SQLite 数据库，固定业务时钟。
这次跑的是实际 Runtime/工具/业务规则，但不是全栈 HTTP 压测；MySQL/Redis/多进程可靠性另有集成验收。
计数/状态/金额/批准/哨兵断言不替代语言答案支持度和用户交互评估。

预算建议：最多12次物理请求、2元预估预算。达到任一限制不再发起新调用；失败/未知响应保留预留。
默认脚本仅 dry-run，真实付费必须由用户配置本地密钥并明确同意。现阶段不另租显卡。
完整执行说明见 deepseek-pilot-plan.md。密钥绝不进聊天、Git、报告或前端。

## 运行证据

- 第一轮 mysql-business-readiness-v1.xml：148 passed，251.25秒；包括真实 MySQL 竞争、
  Redis/Docker 与三个子进程故障场景。其后增加了只读资格咨询和更严格政策主题检查。
- 最终复测：mysql-business-readiness-v2.xml，153 passed，284.44秒，0 failures/errors/skipped。
  主业务/竞争/故障测试使用专用MySQL；workflow评测器回归使用各自独立SQLite；包含Redis/Docker集成，
  不能把153个测试函数参数实例说成153个真实模型任务。
- 最新针对资格咨询等19项业务测试通过；摘要2项通过；既有20条 workflow 继续作为工程回归门禁。
- business-focused-v2.xml：上述业务/摘要/workflow组合41 passed，52.35秒；与全套有重叠，不累计成更多独立场景。
- Ruff check / format check、免费 pilot dry-run、实际 Agent HTTP smoke 已运行通过，无付费调用。

## 不在“准入”承诺内

此处准入只针对受控本地小规模模型联调。不代表全部 R01–R18/L01–L18、生产安全或正式评测通过。
以下仍须继续：

- 全面限流/队列背压/provider 熔断，完整故障与属性测试。
- CSV 沙箱接 Agent 工具、全部资源与孤儿清理验收；当前仍是独立工作台模块。
- 物流人工工单、商品库存与替代品业务；未实现能力明确拒绝。
- 更完整的自然语言多目标消歧、等待问题绑定、目标修改体验与真实模型错误分析。
- 跨地区/品类/生效时段的知识库发布、逐声明语义支持与完整检索消融。
- 应用容器编排、浏览器 QA、备份恢复、远程 CI、生产认证与公开部署。
- 独立审阅的开发/冻结测试集、基线和多次重复实验；公开 benchmark 需单独固定版本与适配。

先用三场景排错，然后扩展多轮开发题；协议和业务错误修正后再冻结测试集，不能用试跑题成绩作简历准确率。
